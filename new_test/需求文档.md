# 需求文档

## 一、背景

你正在 `D:\WorkSpace\agent-verl` 项目中工作。该项目是一个基于 `verl` 框架的强化学习训练系统，核心功能是在 ALFWorld / SciWorld 等交互式环境中训练 LLM Agent。训练流程依赖重量级的分布式基础设施（Ray + FSDP + vLLM），启动和调试成本高。

## 二、核心需求

> **你希望能够绕过训练流程，直接通过接入外部 LLM API（OpenAI-compatible），在 ALFWorld / SciWorld 环境中运行 Agent 的端到端评测。**

具体来说：

1. **接入 API 进行推理**：用 OpenAI-compatible API（如本地部署的 vLLM/SGLang server，或远程 API）替代训练时的本地分布式模型推理，实现 Agent 与环境的多轮交互
2. **最大化复用现有代码**：不重写环境交互逻辑，而是复用已有的 `TrajectoryCollector`（多轮交互循环）、`EnvironmentManager`（环境管理）、`EpisodeRewardManager`（奖励计算）等组件
3. **编写一个独立的、轻量的测试框架**：不需要启动完整的训练 pipeline（无需 critic、ref policy、optimizer 等），只需要一个能直接运行的评测脚本
4. **输出评测指标**：包括 success_rate、episode reward 等，与训练中 `_validate()` 产出的指标对齐

## 三、约束条件

1. **不修改现有训练代码**：新增代码应放在独立目录下（如 `examples/milestone_gae_trainer/eval/`），不应修改已有的 `verl` 框架代码或 `agent_system` 代码
2. **环境依赖保持不变**：仍然使用 Ray 管理环境 worker，但不需要 GPU
3. **配置应简洁**：不使用 Hydra 的复杂配置体系，采用简单的 YAML + OmegaConf 加载方式，支持 CLI override
4. **支持多种环境**：至少支持 ALFWorld 和 SciWorld 两个环境，通过配置切换

## 四、期望的交付物

| 文件 | 类型 | 说明 |
|------|------|------|
| `api_actor.py` | 新建 | API Actor 封装，实现 `generate_sequences` 接口，替代分布式 Actor |
| `eval_config.yaml` | 新建 | 评测专用配置文件（API 端点、环境参数、数据参数） |
| `eval_runner.py` | 新建 | 评测入口脚本，串联所有组件，运行评测循环，输出指标 |
| `run_eval.sh` | 新建 | 启动脚本，设置环境变量并调用 eval_runner.py |

## 五、验收标准

1. 在一个已部署的 OpenAI-compatible API（如本地 vLLM server）上，能通过 `bash run_eval.sh` 一键启动 ALFWorld 评测
2. 评测过程中 Agent 能与环境正常进行多轮交互（观测 → 推理 → 动作 → 环境反馈）
3. 评测结束后输出 `success_rate` 等指标，结果格式与训练中 `_validate()` 的输出一致
4. 通过修改 `eval_config.yaml` 中的 `env.env_name` 和相关参数，能切换到 SciWorld 环境进行评测
5. 通过修改 `api.base_urls` 和 `api.model_name`，能快速切换不同的被测模型
