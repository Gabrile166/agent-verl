## 三、各模块详细设计

### 3.1 `api_actor.py` — APIActorWrapper

这是整个方案中**唯一需要全新编写**的核心模块。它需要实现与 `actor_rollout_wg` 相同的鸭子类型接口。

#### 需要实现的接口

```python
class APIActorWrapper:
    """
    用 OpenAI-compatible API 替代分布式 Actor Worker Group。
    实现 TrajectoryCollector.vanilla_multi_turn_loop() 中所需的全部接口。
    """

    @property
    def world_size(self) -> int:
        """返回 1，消除 pad_dataproto_to_divisor 的影响"""

    def generate_sequences(self, prompts: DataProto) -> DataProto:
        """
        核心方法：接收 tokenized 输入，返回 tokenized 输出。

        输入 prompts.batch 中包含：
          - input_ids:      [batch_size, max_prompt_length]
          - attention_mask:  [batch_size, max_prompt_length]
          - position_ids:    [batch_size, max_prompt_length]  (纯文本环境为 2D)

        输入 prompts.non_tensor_batch 中包含：
          - raw_prompt_ids:  np.ndarray(dtype=object) of List[int]
          - data_source:     np.ndarray(dtype=object) of str  (注意：可能已被 pop)
          - (可选) raw_prompt: np.ndarray(dtype=object) of List[dict]

        输入 prompts.meta_info 中包含：
          - eos_token_id:    int or List[int]
          - pad_token_id:    int

        需要返回的 DataProto.batch：
          - prompts:         [batch_size, max_prompt_length]
          - responses:       [batch_size, max_response_length]  (右侧 pad)
          - input_ids:       [batch_size, max_prompt_length + max_response_length]
          - attention_mask:  [batch_size, max_prompt_length + max_response_length]
          - position_ids:    [batch_size, max_prompt_length + max_response_length]

        需要返回的 DataProto.non_tensor_batch：
          - 透传输入中剩余的 non_tensor_batch 字段（与 vLLM rollout 行为一致）
        """
```

#### 内部处理流程（伪代码级别）

`generate_sequences` 内部需要完成以下步骤：

1. **Decode**：将 `input_ids` 通过 `tokenizer.decode()` 还原为文本 prompt
2. **构建 API messages**：根据 `raw_prompt`（如果有）或 decoded text 构建 `[{"role": "user", "content": ...}]`
3. **并发调用 API**：使用 `asyncio` + `openai` 库并发调用 OpenAI-compatible API 的 `/chat/completions` 端点。支持配置 `temperature`、`max_tokens`、`top_p` 等采样参数
4. **Tokenize response + 追加 EOS**：将 API 返回的文本 response 通过 tokenizer 编码为 token IDs，并在末尾追加 `eos_token_id`。**失败时返回 `[eos_token_id]`（至少保证 1 个有效 token），而非空序列**
5. **构造输出张量（严格对齐 vLLM）**：
   - `responses`：使用 `pad_2d_list_to_length(response_list, pad_token_id, max_length=max_response_length)` 右侧 pad
   - `prompts`：直接取输入的 `input_ids`（已经是 left-padded 的）
   - `input_ids`：`torch.cat([prompts, responses], dim=-1)`
   - `attention_mask`：prompt 部分保持输入的 mask；response 部分使用 `get_response_mask(response, eos_token=eos_token_id)` 生成（**不是简单的 `token != pad`**，而是 EOS 后全部标 0，对齐 [get_response_mask](file:///D:/WorkSpace/agent-verl/verl/utils/torch_functional.py#L190-L210) 的行为）
   - `position_ids`：**复刻 [vllm_rollout_spmd.py L359-369](file:///D:/WorkSpace/agent-verl/verl/workers/rollout/vllm_rollout/vllm_rollout_spmd.py#L359-L369) 的逻辑**：`response_position_ids = position_ids[..., -1:] + torch.arange(1, response_length + 1)`，再 `cat([prompt_position_ids, response_position_ids])`
6. **返回 DataProto**：构造 `DataProto(batch=TensorDict(...), non_tensor_batch=...)`

#### 构造函数参数

```python
def __init__(
    self,
    tokenizer,                    # HF tokenizer 实例
    api_base_urls: List[str],     # API 端点列表（支持负载均衡）
    model_name: str,              # 模型名称
    api_key: str = "EMPTY",
    max_prompt_length: int = 4096,
    max_response_length: int = 2048,
    temperature: float = 0.4,
    top_p: float = 1.0,
    max_tokens: int = 2048,
    max_concurrent: int = 16,     # 最大并发请求数
    timeout: int = 120,
):
```

#### 关键实现注意事项

1. **张量维度对齐**：输出的 `prompts` 和 `responses` 的维度必须精确匹配 `max_prompt_length` 和 `max_response_length`，否则后续 `batch.union()` 时 TensorDict 会因维度不一致报错

2. **Pad Token 处理**：`prompts` 使用 left-padding（已由 `preprocess_batch` 处理），`responses` 使用 right-padding（与 vLLM rollout 行为一致）

3. **Response 截断**：如果 API 返回的 response tokenize 后超过 `max_response_length - 1`（需预留 EOS 位置），截断到 `max_response_length - 1` 后再追加 EOS

4. **EOS 追加与空响应保护**：
   - 每条 response 编码后，末尾追加 `eos_token_id`
   - API 调用失败或返回空时，使用 `[eos_token_id]` 作为 response（至少 1 个有效 token）
   - 这确保 `get_response_mask` 至少标出 1 个有效位置，避免 `EpisodeRewardManager` 计算 `valid_response_length - 1 = -1` 的语义错误

5. **Response Attention Mask 必须使用 `get_response_mask`**：直接导入 `from verl.utils.torch_functional import get_response_mask`，传入 `response_id=responses, eos_token=eos_token_id`。这确保 EOS 后的 pad token 被标为 0，与训练验证行为完全一致

6. **Position IDs 必须对齐 vLLM 实现**：
   ```python
   # 复刻 vllm_rollout_spmd.py L359-369
   response_length = responses.size(1)
   delta_position_id = torch.arange(1, response_length + 1).unsqueeze(0).expand(batch_size, -1)
   response_position_ids = position_ids[:, -1:] + delta_position_id
   position_ids = torch.cat([position_ids, response_position_ids], dim=-1)
   ```

7. **并发控制**：使用 `asyncio.Semaphore` 限制并发数，避免 API 过载。使用轮询策略在多个 `base_urls` 间分配请求

8. **错误重试**：API 调用失败时重试 3 次，最终失败返回 `[eos_token_id]`

9. **`raw_prompt` 优先**：如果 `non_tensor_batch` 中存在 `raw_prompt`（config 设置了 `return_raw_chat=True`），优先使用它构建 API 的 messages（保留完整的 chat 格式），而非从 `input_ids` decode。注意：`raw_prompt` 在 `preprocess_batch` 里由当前 step 的环境观测重新生成（[rollout_loop.py L188-189](file:///D:/WorkSpace/agent-verl/agent_system/multi_turn_rollout/rollout_loop.py#L188-L189)），所以它包含的就是当前轮的用户消息

#### DummyBatch 构造（正式实现项）

当 `data.val_files` 为 null 时，需要构造一个 DummyBatch 作为 `gen_batch` 传入 `multi_turn_loop`。

**必须包含的字段**（基于 [rollout_loop.py L65-66, L188-189, L320, L357-364](file:///D:/WorkSpace/agent-verl/agent_system/multi_turn_rollout/rollout_loop.py#L65-L66) 的访问路径）：

```python
def build_dummy_gen_batch(batch_size, tokenizer, config):
    """
    构造一个形状和类型正确的占位 gen_batch。

    字段需求来源：
    - raw_prompt: preprocess_single_sample L65 必须访问 (但内容会被环境观测覆盖)
    - data_source: preprocess_single_sample L66 必须访问
    - raw_prompt_ids: vanilla_multi_turn_loop L358 pop 到 batch_input
    - input_ids: preprocess_batch L211 通过 len(gen_batch.batch['input_ids']) 获取 batch_size
    - attention_mask: 与 input_ids 同形状
    - position_ids: 与 input_ids 同形状

    gen_batch 的实际 prompt 内容不重要——preprocess_batch 会用环境观测重新生成 input_ids。
    但 raw_prompt 和 data_source 必须是正确类型的 numpy array。
    """
    max_prompt_length = config.data.max_prompt_length

    # 构造一条占位 prompt（内容不重要，形状正确即可）
    dummy_prompt = "Placeholder"
    dummy_chat = [{"role": "user", "content": dummy_prompt}]

    input_ids = torch.full((batch_size, max_prompt_length), tokenizer.pad_token_id, dtype=torch.long)
    attention_mask = torch.zeros((batch_size, max_prompt_length), dtype=torch.long)
    position_ids = torch.zeros((batch_size, max_prompt_length), dtype=torch.long)

    non_tensor_batch = {
        'raw_prompt': np.array([dummy_chat] * batch_size, dtype=object),
        'data_source': np.array([config.env.env_name] * batch_size, dtype=object),
        'raw_prompt_ids': np.array([[tokenizer.pad_token_id]] * batch_size, dtype=object),
    }

    gen_batch = DataProto.from_dict(
        tensors={'input_ids': input_ids, 'attention_mask': attention_mask, 'position_ids': position_ids},
        non_tensors=non_tensor_batch,
        meta_info={
            "eos_token_id": tokenizer.eos_token_id,
            "pad_token_id": tokenizer.pad_token_id,
            "recompute_log_prob": False,
            "do_sample": False,
            "validate": True,
        }
    )
    return gen_batch
```

> **batch_size 必须等于 `data.val_batch_size`**：`vanilla_multi_turn_loop` L323 断言 `len(gen_batch.batch) == len(obs)`，而 obs 来自 `val_envs.reset()`，val_envs 的数量由 `data.val_batch_size` 决定。

## 四、关键实现要点与风险

### 4.1 `generate_sequences` 的输出格式

这是整个方案成败的关键。输出 DataProto 的张量维度必须与 vLLM rollout 的输出完全一致，否则后续 `batch.union()` 和 `gather_rollout_data()` 会出错。

具体而言，需要精确匹配以下维度规范（参考 [vllm_rollout_spmd.py L374-384](file:///D:/WorkSpace/agent-verl/verl/workers/rollout/vllm_rollout/vllm_rollout_spmd.py#L374-L384)）：

| 字段 | Shape | 说明 |
|------|-------|------|
| `prompts` | `[B, max_prompt_length]` | 左侧 pad，与输入的 `input_ids` 相同 |
| `responses` | `[B, max_response_length]` | 右侧 pad，实际 token + EOS + pad token |
| `input_ids` | `[B, max_prompt_length + max_response_length]` | `cat([prompts, responses], dim=1)` |
| `attention_mask` | `[B, max_prompt_length + max_response_length]` | prompt_mask + `get_response_mask(response, eos_token)` |
| `position_ids` | `[B, max_prompt_length + max_response_length]` | prompt 部分保持原值，response 部分 = `prompt_pos[-1] + arange(1, R+1)` |

**编码时需要特别注意**：`position_ids` 在非多模态场景下为 `[B, seq_len]`，多模态场景下为 `[B, 4, seq_len]`（[vllm_rollout_spmd.py L361-362](file:///D:/WorkSpace/agent-verl/verl/workers/rollout/vllm_rollout/vllm_rollout_spmd.py#L361-L362)）。评测场景中只用纯文本环境（ALFWorld、SciWorld），使用 `[B, seq_len]` 即可。

### 4.2 与 `vanilla_multi_turn_loop` 的兼容性

审查 [rollout_loop.py L296-L519](file:///D:/WorkSpace/agent-verl/agent_system/multi_turn_rollout/rollout_loop.py#L296-L519) 中的 `vanilla_multi_turn_loop`，确认以下兼容性要求：

1. **`pad_dataproto_to_divisor(batch_input, actor_rollout_wg.world_size)`** (L373)
   - `APIActorWrapper.world_size = 1` → pad_size 始终为 0，等价于 no-op ✅

2. **`batch.union(batch_output)`** (L381)
   - 要求 `batch_output.batch` 与 `batch.batch` 的 batch_size 相同
   - `batch` 此时已经 pop 掉了 `input_ids`/`attention_mask`/`position_ids`
   - `batch_output` 需要提供这些字段的完整版（prompt+response 拼接后的）✅

3. **`tokenizer.batch_decode(batch.batch['responses'])`** (L383)
   - 要求 `responses` 是 valid token IDs（包含 EOS 后的 pad 不影响 decode）✅

4. **`batch.non_tensor_batch['uid']` / `batch.non_tensor_batch['traj_uid']`** (L378-L379)
   - 这些是在 union 之前设置的，与 generate_sequences 无关 ✅

5. **`envs.reset(kwargs=gen_batch.non_tensor_batch.pop('env_kwargs', None))`** (L320)
   - DummyBatch 中 `env_kwargs` 不存在，`pop` 返回 None，安全 ✅

### 4.3 `multi_turn_loop` 中 `is_train=False` 的路径

审查 [rollout_loop.py L593-L760](file:///D:/WorkSpace/agent-verl/agent_system/multi_turn_rollout/rollout_loop.py#L593-L760) 中的 `multi_turn_loop`：

当 `is_train=False` 时：
- 不调用 `gen_batch.repeat()`（L612-613 被跳过）
- 不使用 `dynamic_multi_turn_loop`（L616 条件不满足）
- 直接走 `vanilla_multi_turn_loop`（L626）
- 不保存 trajectory 到磁盘（L742 `is_train` 为 False）
- `rlvmr` 模块导入失败会打印日志但不阻塞（L655-668, L673-739）— **已知可接受噪声**

### 4.4 环境初始化的 Ray 依赖

`make_envs()` 内部调用 `build_alfworld_envs()` / `build_sciworld_envs()`，这些函数创建 Ray Actor 作为环境 worker。因此：

- **需要初始化 Ray**，统一由 `eval_runner.py` 中 `ray.init()` 管理
- **Ray CPU 计算**：`make_envs()` 会同时创建 train 和 val 两组环境（[env_manager.py L1221-1222](file:///D:/WorkSpace/agent-verl/agent_system/environments/env_manager.py#L1221-L1222)），即使 eval 只使用 val_envs。因此需要：
  ```python
  ray_num_cpus = int((config.data.train_batch_size * config.env.rollout.n
                       + config.data.val_batch_size)
                      * config.env.resources_per_worker.num_cpus) + 2  # +2 for driver overhead
  ray.init(num_cpus=ray_num_cpus)
  ```
- **不需要 GPU**

### 4.5 `gen_batch.meta_info` 的构造

在 `_validate()` ([ray_trainer.py L996-L1003](file:///D:/WorkSpace/agent-verl/verl/trainer/ppo/ray_trainer.py#L996-L1003)) 中，`test_gen_batch.meta_info` 被设置了以下字段：

```python
meta_info = {
    "eos_token_id": tokenizer.eos_token_id,
    "pad_token_id": tokenizer.pad_token_id,
    "recompute_log_prob": False,
    "do_sample": False,    # eval 时通常 greedy
    "validate": True,
}
```

`eval_runner.py` 中构造 gen_batch 时必须设置这些字段。特别是 `eos_token_id`，因为 `APIActorWrapper.generate_sequences` 需要从 `meta_info` 读取它来构造 response mask 和追加 EOS token。

### 4.6 API 模型与 Tokenizer 兼容性

`model.path` 仅用于加载 tokenizer，`api.model_name` 用于远端模型。这很灵活但有风险：

- 如果远端模型和本地 tokenizer 不是同一模型家族，response 的 retokenize、EOS token、pad token 行为可能不一致
- **默认要求**：`model.path` 的 tokenizer 必须与 API 服务的模型兼容（同族模型）
- **不兼容时**：结果仅保证环境动作文本可用（decode → step 的链路不受影响），不保证与训练验证指标严格一致
